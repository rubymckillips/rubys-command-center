# Part B Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Inline execution respects Ruby's limited credits.

**Goal:** Deploy GitHub login, durable sessions, private workspaces, and owner/member access.
**Architecture:** Node handles GitHub authorization-code/PKCE and Postgres sessions. Existing repositories are scoped by workspace; the static frontend proxies /api to keep cookies same-origin.
**Tech Stack:** React, Node 22, node:crypto, fetch, pg, Postgres, Vitest, Render.
**Spec:** ../specs/2026-10-14-github-sign-in-design.md

## Global constraints

- Preserve production records and existing service URLs.
- No provider tokens, private emails, or secrets in source or logs.
- Every production request scopes data to authenticated GitHub identity.
- Existing private feed integrations remain disabled in production.
- No paid hosting changes or additional sign-in providers.
